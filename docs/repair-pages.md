# Шаблон страниц ремонта

В админке: **Услуги → Страницы ремонта → Создать**. Все записи используют дизайн страницы «Пакетный ремонт» и общий шаблон `site/repair-page`; копировать CMS-страницы или вёрстку не требуется.

1. Укажите название — оно станет H1 — и адрес латиницей с дефисами.
2. Заполните Title и Description на вкладке «SEO». Пустой Title заменяется названием страницы; Description не копируется с другой страницы.
3. При необходимости замените изображения, тексты преимуществ, подписи пяти карточек, этапы, заголовок портфолио и тексты формы заявки.
4. Добавьте собственные SEO-блоки и вопросы с ответами. Пустые списки скрывают соответствующие секции; чужой SEO-текст и FAQ не подставляются.
5. Опубликуйте запись. Черновики, выключенные записи, будущие публикации и просроченные страницы возвращают HTTP 404 и не попадают в sitemap.xml.

Примеры адресов:

| Название | Slug | URL |
| --- | --- | --- |
| Ремонт однокомнатной квартиры | remont-odnokomnatnoj-kvartiry | /repairs/remont-odnokomnatnoj-kvartiry |
| Ремонт двухкомнатной квартиры | remont-dvuhkomnatnoj-kvartiry | /repairs/remont-dvuhkomnatnoj-kvartiry |

Примеры не создаются автоматически. Опубликованные страницы автоматически получают собственный canonical, og:url, хлебные крошки и запись в карте сайта. При заполненном FAQ выводится соответствующая разметка FAQPage. Ссылку в меню нужно добавить отдельно, если она нужна.

## Общие и индивидуальные данные

Пустые изображения, вводный блок и этапы наследуются из **Услуги → Пакетный ремонт**. Подписи карточек, основной текст преимуществ и тексты заявки имеют исходные значения шаблона. Заполненное поле страницы заменяет общее значение. Очистка списка этапов возвращает общие этапы. SEO и FAQ всегда индивидуальны.

Тарифы берутся из **Тарифы ремонта**; подборка портфолио общая со страницей `/repairs`. Форма использует существующий обработчик сайта и передаёт адрес страницы заявки. Название может быть длинным: для новых страниц предусмотрены переносы на узких экранах.

## Установка

После переноса изменённых файлов выполнить в целевой установке October CMS:

```sh
php artisan tailor:migrate --no-interaction
php artisan cache:clear
```

Миграция создаёт отдельную сущность `Site\RepairPage`. Существующие данные `Site\Services`, тарифы и кейсы не переносятся и не перезаписываются. Сначала применить миграцию, затем проверять динамические страницы и sitemap.

Интеграционная проверка выполняется только в отдельной локальной или тестовой установке с применёнными миграциями. Скрипт создаёт временные записи и откатывает изменения базы транзакцией:

```sh
# Запуск из корня тестовой установки October, не из корня репозитория.
KV_REPAIR_PAGES_LOCAL_TEST=1 php /path/to/kv-tyumen/scripts/test-repair-pages.php
```

Проверяются независимость контента, общие тарифы и этапы, метаданные, FAQ JSON-LD, canonical, крошки, карта сайта, состояния публикации и 404.
